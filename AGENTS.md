# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- **What this repo is**: a sequenced io_uring curriculum (`curriculum/`) plus runnable samples (`code/`) plus honestly-dated resource curation (`resources/`). See the root `README.md` for the pitch and `curriculum/README.md` for the stage table.
- **This repo requires a real Linux kernel to run samples, not just compile them** — unlike the CUDA repo in this series (which had no GPU available), io_uring samples in this repo genuinely run: `docker run --rm -it --security-opt seccomp=unconfined ubuntu:24.04` (Linux 6.12.76-linuxkit here, arm64 Docker Desktop VM) is the verified environment. `--security-opt seccomp=unconfined` is required — Docker's default seccomp profile blocks the io_uring syscalls since Docker 25.0 (moby/moby#46762), which `code/07-security` demonstrates on purpose. Never claim a sample was run or a number measured without actually running it in this environment or an equivalent — see `code/README.md`'s "How this was verified" section for the exact wording this repo uses.
- **Benchmark numbers are real and sometimes counter-narrative on purpose**: `code/05-file-copy` shows io_uring losing to plain `read()`/`write()` on sequential copy and winning 11–23× on random reads; `code/08-capstone` shows io_uring as the *slowest* of io_uring/epoll/blocking on a trivial-per-connection echo benchmark; `code/06-sqpoll` shows SQPOLL roughly a wash. Do not "fix" these to match the common "io_uring is always faster" narrative — they are honest, reproduced measurements and the whole point of the house standard this repo follows (see `resources/common-pitfalls.md`'s "measuring, not assuming" section). If re-measuring produces a different result, update the number and the explanation together; don't just restate the old narrative.
- **Adding a sample**: one or more `.c` files + `Makefile` + `README.md` per directory under `code/`, following the existing numbered-stage naming (`0N-topic-name`). Every sample uses `code/common/common.h`'s `CHECK_RC` (for liburing/raw-syscall calls returning `-errno`) and `CHECK_ERRNO` (for libc calls returning `-1` + setting `errno`) — don't invent a new error-checking pattern. Every `Makefile` needs a `test` target CI can run non-interactively (see `.github/workflows/ci.yml`).
- **Citation discipline**: every external link in `curriculum/*.md` and `resources/*.md` must be a URL someone actually fetched and confirmed live — this was the explicit standard the repo was built to. Before adding or changing a citation, fetch the URL yourself; don't restate one from memory. This caught a real error during the repo's own construction: an early source claimed `shuveb/loti` and `shuveb/io_uring-by-example` were recently active, but a direct fetch showed both pushed in 2024 — over a year stale. Trust your own fetch over any secondhand claim, including this file's.
- **Kernel-version-to-feature mapping** (what needs 5.1 vs. 5.19 vs. 6.0 vs. 6.1) lives in `curriculum/00-toolchain-setup.md`, cited from kernelnewbies.org — check there before asserting a version requirement elsewhere.
